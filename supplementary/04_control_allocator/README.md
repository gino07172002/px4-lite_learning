# 補充模組 04: 控制分配器與優先級消飽和策略 (Control Allocator & Desaturation)

## 1. PX4 原始碼對照與設計背景

在 PX4 v1.13 之後，官方徹底廢棄了舊版靜態文字混控器（`.mix` 檔案），全面轉向現代化模組：
- `src/modules/control_allocator`
- `src/lib/control_allocation`

### 為什麼不能只用簡單的線性加減混控（Lab 05 做法）？
假設飛機正以 90% 大油門急速爬升（$T = 0.9$），此時遭遇強烈陣風，姿態控制器急需產生滾轉扭矩 $u_{roll} = 0.3$：
```
若使用直覺線性加法：
M_left  = T + u_roll = 0.9 + 0.3 = 1.2  ──(硬截斷至 1.0)──> 1.0
M_right = T - u_roll = 0.9 - 0.3 = 0.6  ──(正常輸出)────────> 0.6
```
- **悲劇後果**：左馬達被截斷在 1.0，推力差只有 $1.0 - 0.6 = 0.4$（期望推力差為 $0.6$）。
- **機體扭矩嚴重縮水 33%！** 飛機無法及時修正滾轉角度，隨後在強風中翻滾失控墜毀！

## 2. PX4 動態消飽和核心架構 (Priority-Based Desaturation)

PX4 的 `ControlAllocation` 實施了嚴格的**物理優先級裁決（Priority Hierarchy）**：
```
  [ 優先級 1: 滾轉/俯仰自穩 (Roll / Pitch) ] ── (最高優先級，確保飛機不翻機)
                       │
  [ 優先級 2: 垂直推力高度 (Thrust) ]        ── (次要，允許暫時降高以換取姿態自穩)
                       │
  [ 優先級 3: 偏航旋轉控制 (Yaw) ]           ── (最低優先級，必要時最先被閹割)
```

### 消飽和降推力演算法 (Upper Saturation Desaturation)
1. 依據分配矩陣計算出初版馬達需求 $m_i$。
2. 尋找最大馬達需求：$m_{max} = \max(m_i)$。
3. 若 $m_{max} > 1.0$，說明馬達已頂到輸出天花板：
   - 計算超額量：$\Delta T = m_{max} - 1.0$
   - **集體下調所有馬達的平均推力**：$m_i \leftarrow m_i - \Delta T$
4. **結果**：完全保留了左右馬達的相對推力差（$100\%$ 保全 Roll 自穩扭矩），僅短暫犧牲少許垂直升力，換取整機絕對不翻滾！
