# Lab 07: Commander + Failsafe (飛行狀態機與安全保護系統)

## 1. Lab 目標與設計理念

在飛控軟體中，**Commander（指揮官模組）** 是整架無人機的「大腦總管」：
- 它不直接控制馬達轉速，而是管理整機的**生命週期有限狀態機（Finite State Machine, FSM）**。
- 負責：解鎖（Arming）、上鎖（Disarming）、起飛（Takeoff）、降落（Landing）。
- **最核心使命：安全守門人（Safety Gatekeeper）**。
  - 解鎖前嚴格執行健康檢查（Pre-arm Checks），感測器異常時**堅決拒絕解鎖**。
  - 飛行途中持續監控硬體健康，一旦發生關鍵感測器失效（如 IMU 逾時），自動切換至 **Failsafe（失效保護機制）** 執行自動緊急降落。

## 2. 狀態機轉移圖 (State Diagram)

```
        [ INIT ]
           │ (系統自檢完成)
           ▼
     ┌──────────────┐   arm (健康檢查 PASS)   ┌─────────────┐
     │   STANDBY    │ ──────────────────────> │    ARMED    │
     │ (待機已上鎖) │ <────────────────────── │ (已解鎖怠速)│
     └──────────────┘         disarm          └─────────────┘
           ▲                                         │
           │                                         │ takeoff
           │                                         ▼
     ┌──────────────┐          land           ┌─────────────┐
     │   LANDING    │ <────────────────────── │   FLYING    │
     │  (自動降落)  │                         │ (自主飛行中)│
     └──────────────┘                         └─────────────┘
           ▲                                         │
           │           感測器超時 / 嚴重故障         │
           └──────────────── FAILSAFE ◀──────────────┘
```

## 3. 三個實現階段說明

### 階段一：基礎版（Stage 1 - 核心有限狀態機）
- **重點**：定義 State 與 Command 列舉，實作狀態轉移表。
- **原則**：防範非法轉移（如未 Arming 就要求 Takeoff 必須予以拒絕）。

### 階段二：核心進階版（Stage 2 - 預解鎖健康檢查 Pre-arm Checks）
- **重點**：對標 PX4 解鎖前檢查機制。
- **機制**：
  - 整合 `imu_ok`, `estimator_ok`, `battery_ok` 等健康狀態。
  - 當任何一項為 false 時，呼叫 `arm()` 會回傳 `ARM DENIED`，並輸出精確拒絕原因。

### 階段三：PX4 對標進階版（Stage 3 - 飛行中心跳監控與自主 Failsafe）
- **重點**：飛行途中背景健康監控（Heartbeat Monitor）。
- **機制**：
  - 飛行狀態下，若 IMU 數據中斷超過 200ms，系統立即觸發緊急事件。
  - 自動轉移：`FLYING -> FAILSAFE -> AUTO_LANDING -> STANDBY`。
  - 涵蓋 8 項完整單元測試。

## 4. 驗收標準與測試清單

- [x] 完整生命週期測試通過：`INIT -> STANDBY -> ARMED -> FLYING -> LANDING -> STANDBY`。
- [x] 感測器不健康時，解鎖指令被安全攔截並提示原因。
- [x] 飛行中注入感測器故障，系統毫秒級切換至 FAILSAFE 緊急降落。
- [x] 任何非法狀態躍遷均被阻擋。
